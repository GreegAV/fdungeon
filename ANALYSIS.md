## Огляд проєкту

Мережевий текстовий MUD-сервер, родовід DikuMUD → Merc → ROM 2.4, з великим шаром
власних доробок команди Forgotten Dungeon (1998–2005). Telnet, порт 4000 за
замовчуванням.

| Метрика | Значення |
|---|---|
| Код | 87 563 рядки, 40 `.c` + 13 `.h` |
| Дані зон | 129 `.are`, 257 416 рядків, 7.2 MB |
| Команди | ~354 у `cmd_table`, 389 функцій `do_*` |
| Історія git | 85 комітів (CVS втрачено, ранню історію збережено в `changes.txt`) |
| Розмір `.git` | 6.2 MB |

**Найбільші модулі:**

| Файл | Рядків | Призначення |
|---|---|---|
| `db.c` | 5926 | завантаження зон, boot_db, пул рядків |
| `act_wiz.c` | 5650 | команди імморталів |
| `fight.c` | 5290 | бойова система |
| `magic.c` + `magic2.c` | 8595 | заклинання |
| `saboteur.c` | 4329 | власні фічі FD: голосування, шлюби, газета, penalties, travel |
| `const.c` | 4574 | таблиці рас, класів, скілів |
| `olc_act.c` | 4417 | онлайн-редактор зон |

**Архітектура.** Однопотоковий процес: `main()` (`comm.c:283`) → `init_socket()` →
`boot_db()` → `game_loop_unix()`. Цикл крутить `select()` по всіх дескрипторах,
4 пульси на секунду (`PULSE_PER_SECOND = 4`). Пам'ять — freelist-пули (`mem.c`,
`recycle.c`) плюс монолітний `string_space` на 8.3 MB (`MAX_STRING`). Персонажі
зберігаються текстовими файлами в `player/`, зони — текстові `.are` зі вбудованим
OLC-редактором.

**Кодування.** Вихідники в CP1251 (російськомовні ігрові повідомлення),
`charset.c` конвертує вивід під кодування клієнта (koi8 / cp866 / cp1251 / utf8).
З комітів видно, що підтримку UTF-8 доробили лише частково.

## 0. Збірка через CMake не працює — ВИПРАВЛЕНО

`CMakeLists.txt` зламаний з двох незалежних причин.

### 0.1 Зайві файли, що не компілюються

У списку джерел є `mud/autors.c` і `mud/printf.c`. Обох нема в `mud/Makefile` —
і не випадково: разом вони дають **87 помилок компіляції**.

* `autors.c` — на початку файлу відсутній відкриваючий `/*` перед блоком копірайтів,
  тому весь текст парситься як код: `stray '\356' in program`, `unknown type name 'Diku'`.
* `printf.c` — **не** мертвий код, як здалося спочатку. Це фрагмент тіла функції,
  який підключається через `#include "printf.c"` у п'ятьох місцях: `comm.c:3583`
  та `io.c:1000, 1022, 1051, 1088`. Файл має залишитись на диску, але не повинен
  компілюватись як окрема одиниця трансляції — саме тому його нема в `Makefile`.

### 0.2 Відсутній `-fcommon`

GCC 10 і новіші за замовчуванням вмикають `-fno-common`. `merc.h` містить **159
tentative-визначень глобальних змінних** (без `extern`), які потрапляють у кожну
одиницю трансляції. Без `-fcommon` лінковка падає з **550 помилками**:

```
/usr/bin/ld: act_info.o:(.bss+0x98): multiple definition of `max_skill';
             act_comm.o:(.bss+0x98): first defined here
/usr/bin/ld: act_info.o:(.bss+0x80): multiple definition of `PULSE_VIOLENCE'; ...
```

`mud/Makefile` цей прапорець має (`C_FLAGS = -O1 -I/usr/include -I. -DOLD_RAND -Wall -fcommon`),
`CMakeLists.txt` — ні.

### Виправлення — зроблено

```cmake
add_compile_options(-fcommon -Wall)
add_compile_definitions(OLD_RAND)

        mud/autors.c    # видалено зі списку джерел
        mud/printf.c    # видалено зі списку джерел
```

Лишилось 38 `.c`-файлів — рівно набір з `mud/Makefile`. Перевірено складанням
тим самим набором прапорців: **0 помилок, 0 попереджень**, бінарник 1.7 MB
лінкується.

**Правильне рішення в перспективі** — прибрати tentative-глобали з `merc.h`:
залишити в заголовку `extern`-оголошення, а самі визначення перенести в один
`.c`-файл (наприклад `globals.c`). Тоді `-fcommon` більше не потрібен. Це ~159
змінних, робота на пів дня, але вона знімає залежність від застарілої семантики
компілятора.

## 2. Мертвий код для неіснуючих операційних систем

`comm.c:82–260` — приблизно 179 рядків ручних прототипів функцій libc для
платформ, які не існують з 90-х:

`_AIX`, `apollo`, `__hpux`, `interactive`, `MIPS_OS`, `NeXT`, `sequent`, `sun`,
`ultrix`, `SYSV`.

Жоден із цих блоків не компілюється на Linux/GCC і жоден не потрібен. Всередині
них є й прямі пошкодження від невдалого find/replace, наприклад `comm.c:94`:

```c
int socket args( ( int docomm.cmain, int type, int protocol ) );
//                    ^^^^^^^^^^^^ мало бути "domain"
```

Рядок знаходиться всередині `#if defined(_AIX)`, тому на Linux нешкідливий — але
показує, що подібні артефакти можуть бути й деінде.

**Дія:** видалити всі блоки, крім `#if defined(linux)` і `#if defined(WIN32)`.

## 3. `int abs(int)` перевизначає функцію стандартної бібліотеки

`merc.h:507` оголошує `int abs(int a);`, `saboteur.c:2537` її визначає:

```c
int abs(int number)
{
 if (number<0) return -number;
 return number;
}
```

### Чому це проблема

GCC розпізнає `abs` як вбудовану функцію і не викликає визначення з `saboteur.c`.
Перевірено на `gcc -O1`:

```c
int abs(int a);
int f(int x){ return abs(x); }
```
```asm
f:  movl %edi,%eax ; negl %eax ; cmovs %edi,%eax ; ret
```

Виклику нема — компілятор підставив інструкції напряму.

Наслідок: на `-O1` (як у `Makefile`) працює вбудована реалізація, на `-O0`
(як у конфігурації CLion Debug) — та, що в `saboteur.c`. Зараз обидві поводяться
однаково, тому різниці не видно. Але будь-яка майбутня правка в `saboteur.c:2537`
мовчки застосується **тільки до Debug-збірки** — це саме той клас багів, який
потім ловлять тижнями.

Окремо: `abs` — зарезервоване стандартом ім'я, і визначати власну версію формально
є невизначеною поведінкою (C11 7.1.3).

### Виправлення (~1 хвилина)

1. Видалити `merc.h:507`.
2. Видалити `saboteur.c:2537–2541`.
3. Додати `#include <stdlib.h>` у `update.c`.

Крок 3 обов'язковий: `abs` викликається в чотирьох файлах, і `update.c` (5 викликів)
єдиний, де `stdlib.h` ще не підключений. У `db.c`, `quest.c`, `saboteur.c` він уже є.

## 4. `system()` блокує весь сервер — ВИПРАВЛЕНО (вимкнено)

### Чого тут нема

Ін'єкції команд нема. Ім'я гравця підставляється в шелл-рядок, але
`check_parse_name` (`comm.c:1606`) пропускає лише `isalpha`, довжина 3–12 символів.
Шелл-метасимволи — ASCII-пунктуація — не проходять.

### Що тут є

FD однопотоковий. `system()` робить `fork` + `/bin/sh -c` і **чекає завершення
дитини**. Весь цей час `game_loop_unix` не крутиться, і гра стоїть для всіх гравців.

Тепер дивимось, що саме запускається:

```bash
# areas/notify_tg.sh
/usr/bin/curl -k -H "${HEADER}" --data-urlencode "text=${1}" \
  "https://api.telegram.org/${BOTID}:${TOKEN}/sendMessage?..."
```

Ні `--max-time`, ні `--connect-timeout`, ні `&` у кінці.

| Місце | Тригер | Що робить |
|---|---|---|
| `comm.c:2673` | **кожен вхід гравця у світ** | HTTPS-запит до Telegram |
| `note.c:447` | кожна написана нотатка | `iconv` + HTTPS-запит до Telegram |
| `act_wiz.c:4806` | `cr_rep()` при ремoрті | `mail -s IStartAlert saboteur@saboteur.com.ua` |

Якщо `api.telegram.org` недоступний або відповідає повільно, дефолтний TCP-таймаут
curl складає **понад 2 хвилини**. Весь MUD висить увесь цей час. Якщо провайдер
блокує з'єднання мовчки і воно застрягає в `SYN_SENT` — сервер мертвий доти,
доки не спрацює системний таймаут.

`act_wiz.c:4806` до того ж має хардкод поштової адреси, а `mail` на сучасному
Linux зазвичай навіть не встановлений.

### Виправлення

**Мінімальне (5 хвилин, закриває більшість ризику).** У `areas/notify_tg.sh` і
`areas/send_note.sh`:

```bash
/usr/bin/curl --max-time 5 --connect-timeout 3 -k -H "${HEADER}" ... &
disown
```

Гра стоятиме лише на час `fork`.

**Правильне.** Замінити `system()` на `fork()` + `execl()` без `wait()`, з
`signal(SIGCHLD, SIG_IGN)`, щоб не накопичувались зомбі-процеси. Змінна `exitcode`
при цьому втрачає сенс, відповідні `log_printf` треба переписати.

**Зроблено.** Обидва Telegram-виклики загорнуті в `#if 0` з поясненням:
`comm.c:2668` (сповіщення про вхід) і `note.c:441` (сповіщення про нотатку).
Код збережений, вмикається зняттям `#if 0`.

**Не чіпалось:** `act_wiz.c:4806` (`mail -s IStartAlert ...`) — це не Telegram,
а пошта, і воно спрацьовує лише при ремoрті. Якщо `mail` не встановлений,
`system()` завершиться миттєво з ненульовим кодом, тому блокування там нема.
Якщо вирішиш вмикати TG назад — спершу додай у скрипти
`--max-time 5 --connect-timeout 3` і `&`.

## 5. Решта

### 5.1 Переповнення стека в `string_format` — ВИПРАВЛЕНО

Це єдиний пункт цього розділу, який не є косметикою.

`string.c:372`, з авторським коментарем прямо над функцією:

```c
// THIS FUNCTION IS NOT CHECKED - I'LL REWRITE IT LATER. (c) Invader
const char * string_format (const char * oldstring)
{
  char xbuf[MAX_STRING_LENGTH];    // 4096
  char xbuf2[MAX_STRING_LENGTH];
```

Ланцюжок досяжності:

1. `string_add` (`comm.c:642`) — редактор тексту, доступний будь-якому гравцю
   через `note write` або редагування опису персонажа.
2. Довжина тексту обмежена `MAX_STRING_LENGTH - 6` = **4090 байт** (`string.c:99`).
3. Команда `.f` у редакторі → `string.c:142` → `string_format`.
4. Функція переносить рядки по 77 символів і на кожен додає
   `strcat(xbuf, "\n\r")` — **плюс 2 байти на рядок**.

Арифметика: 4090 / 77 ≈ 53 рядки × 2 = **~106 байт понад 4096**.

Додатково, у першому циклі (`string.c:380–467`) взагалі відсутня перевірка `i`
перед записами `xbuf[i+1]`, `xbuf[i+2]`, `xbuf[i+3]` при розстановці подвійних
пробілів після крапки — там буфер росте ще швидше.

Практично це виглядає так: гравець пише довгу нотатку, тисне `.f`, стек за `xbuf`
затирається. Найімовірніший результат — segfault. Оскільки в `main()` встановлено
`signal(SIGSEGV, segmentation_handler)`, це виглядатиме як випадковий креш, а не
як атака, і шукати причину буде важко.

**Зроблено.** У `string.c:372`:

* `xbuf` і `xbuf2` збільшені до `MAX_STRING_LENGTH * 2`;
* перший прохід обмежений `if (i >= MAX_STRING_LENGTH - 8) break;` — тобто
  другому проходу (перенос рядків) гарантовано лишається 4 KB запасу під `\n\r`;
* закриті читання за межу буфера: `xbuf[i-1]` при `i == 0` (два місця) і
  `xbuf[i-1]/[i-2]/[i-3]` при `i < 3` (два місця);
* закритий underflow у фінальному `xbuf[strlen(xbuf)-2]` на порожньому результаті.

Перевірено окремим стендом під `-fsanitize=address,undefined`:

| Вхід | До правки | Після правки |
|---|---|---|
| 4090 байт без переносів | `*** buffer overflow detected ***` | 4146 байт, чисто |
| 4090 байт із крапкою через символ | `*** buffer overflow detected ***` | 4143 байти, чисто |
| `""`, `" "`, `"\n\n\n"`, `"a"` | читання за межу буфера | чисто |

### 5.2 `strcat` / `strcpy`

701 виклик `strcat`, 99 `strcpy` проти 2 `snprintf`. Цифра виглядає страшно, але
переважна більшість — це `strcat(buf, " literal")` у побудові рядків з назвами
прапорців, де сума літералів свідомо менша за буфер. Небезпечні лише ті, де
джерело є змінною (близько 60 місць): `strcat(final, buf)` в `olc.c:892` і далі,
`strcat(buf1, buf)`, `strcat(xbuf, p)`.

З них реально доводжуваним є тільки випадок 5.1. Решту варто чіпати лише за
конкретним крешем — масовий рефакторинг тут дасть більше регресій, ніж користі.

### 5.3 Об'єктні файли належать root

38 файлів `mud/*.o` мають власника `root` — колись збірка запускалась через `sudo`.
Тепер звичайний `make` або не зможе їх перезаписати (`Permission denied`), або
мовчки використає застарілі об'єктники. Лікується: `sudo rm mud/*.o`.

Додано `.idea/`, `cmake-build-debug/`, `cmake-build-*/`.

`CMakeLists.txt` досі не закомічений — це варто зробити, інакше CLion-збірка не

### 5.5 Робочі дані гравців у git

Закомічені `log/notes.not`, `log/complain.not`, `log/bugreport.not`,
`log/penal.not`, `log/news.not`, `log/ideas.not`, `log/chang.not`, `log/ban.txt`.
Це контент, який сервер генерує і переписує під час роботи. Наслідок: після
кожного запуску `git status` брудний, а `git pull` на живому сервері даватиме
конфлікти злиття.

Цікаво, що `.gitignore` уже містив чотири з них (`bugreport.not`, `complain.not`,
`offtopics.not`, `penal.not`) — але правила `.gitignore` не діють на файли, які
вже під версійним контролем, тому вони й далі відстежувались.

**Зроблено.** Правило узагальнене до `log/*.not` + `log/ban.txt`, і вісім файлів
знято з відстеження через `git rm --cached`. Самі файли залишились на диску.
`log/log.fil` навмисно залишений у git — він тримає існування каталогу `log/`
після свіжого клону.
