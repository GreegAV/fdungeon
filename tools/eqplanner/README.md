# FDungeon — планувальник екіпіровки

Локальний веб-застосунок: обираєш рівень персонажа та alignment — отримуєш
перелік шмоток і зброї, які такий персонаж може вдягнути, з identify обраного
предмета та підсумковими статами.

```
┌──────────────┬─────────────────────────┬──────────────────┐
│              │  Свет     [ ... ▾ ]     │                  │
│   ASCII      │  Голова   [ ... ▾ ]     │    identify      │
│   силует     │  Шея      [ ... ▾ ]     │    обраного      │
│  (const.c)   │  ...      [ ... ▾ ]     │    предмета      │
├──────────────┴─────────────────────────┴──────────────────┤
│ hitroll · damroll · armor class · saves · hp/mana · вага   │
└────────────────────────────────────────────────────────────┘
```

## Запуск

```sh
python3 tools/eqplanner/extract_data.py   # разово: areas/*.are + const.c -> JSON
python3 tools/eqplanner/serve.py          # http://127.0.0.1:8765/
```

Потрібен лише Python 3 зі стандартної бібліотеки. Сторінка статична —
`serve.py` існує тільки тому, що браузер не дає `fetch` до `file://`.
Будь-який інший статичний сервер підійде так само:

```sh
python3 -m http.server 8765 --directory tools/eqplanner/web
```

Дані перечитуються лише скриптом видобування, тож після правок в `areas/` або
в `mud/const.c` запусти `extract_data.py` ще раз.

## Що звідки береться

Застосунок нічого не вигадує — усе змодельовано з коду MUD-а:

| Що                       | Звідки                                                            |
|--------------------------|-------------------------------------------------------------------|
| предмети                 | `areas/*.are`, секції `#OBJECTS`, читач повторює `db.c:load_objects()` |
| перелік областей         | `#AREADATA` (`db.c:load_area()`) — назва, `Credits <lo hi>`, `Security` |
| ASCII силует             | `where_name_male` / `where_name_female` у `mud/const.c`            |
| порядок і назви слотів   | `wear_l[]` у `mud/tables.c`                                        |
| у який слот лягає річ    | `act_obj.c:wear_obj()`                                             |
| заборона за alignment    | `handler.c:equip_char()` (`ITEM_ANTI_GOOD` / `_EVIL` / `_NEUTRAL`) |
| заборона за рівнем       | `act_obj.c:wear_obj()` — `ch->level < obj->level`                  |
| armor class              | `handler.c:apply_ac()` + `equip_char()`                            |
| hitroll/damroll/saves    | `handler.c:affect_modify()`                                        |
| підсумок saves           | `magic.c:calc_saves()`, показ як у `do_score`                      |
| картка identify          | `magic2.c:spell_identify()`                                        |
| відмінки в назвах        | `comm.c:gram_newformat()` — формат `основ\|а\|и\|і…`               |
| кольори `{c`             | `comm.c:colour()` + ANSI-коди з `merc_def.h`                       |

Кілька наслідків, які видно в цифрах і які саме такі в коді:

* `wear_obj()` — це ланцюжок гілок з `return`, тож річ потрапляє **лише в першу**
  групу, чий прапорець вона має. Меч із прапорцями `take/legs/wrist/wield`
  залишається зброєю: гілка `wield` спрацьовує раніше за `legs`.
* Щити, held-предмети і зброя всі йдуть у `WEAR_RHAND`/`WEAR_LHAND`, а в
  `apply_ac()` немає гілки для цих слотів (як і для пальців). Тому значення
  броні щита не рахується — працюють тільки його `ac`-applies. Панель identify
  каже про це прямо.
* `calc_saves()` множить `saving_throw` залежно від рівня, тому підсумок saves
  змінюється, коли міняєш рівень, навіть якщо набір той самий.

## Керування

* **Рівень / Alignment** — головний фільтр: показуються тільки речі, які
  персонаж справді вдягне.
* **Клас / Стать** — вибирають ASCII-силует (`const.c` має по картинці на клас).
* **Рівень предмета від** — відсікає низькорівневий мотлох (наприклад речі
  0-го рівня, які носять моби).
* **Області** — за замовчуванням вимкнені божественні області: ті, чий
  діапазон у `Credits` починається зі 101+, і ті з `Security 9` (редагує лише
  імплементор). Саме там лежать речі з п'ятизначним hitroll. Вибір
  зберігається в `localStorage`.
* **Автопідбір** — ставить у кожен слот найкраще за простою ваговою оцінкою
  (damroll > hitroll > стати > AC). Це підказка, а не істина.
* **Посилання** — набір кодується в URL, тож ним можна поділитися.
* Клік по рядку силуету перестрибує на відповідний слот.

## Файли

```
tools/eqplanner/
  extract_data.py     читач .are + const.c -> web/data/*.json
  serve.py            статичний сервер для web/
  web/
    index.html
    css/style.css
    js/mud.js         правила MUD-а (кольори, відмінки, apply_ac, calc_saves)
    js/app.js         UI
    data/*.json       згенеровані дані (не редагувати руками)
```

`extract_data.py --all` читає всі `areas/*.are`, а не лише перелічені в
`areas/area.lst` (те, що справді вантажить MUD). `--pretty` пише JSON
з відступами, якщо треба почитати очима.
